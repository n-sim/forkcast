# Forkcast for Android

The Android app is the same React frontend and Rust application core as the
desktop app, built as a Tauri 2 mobile project from `crates/desktop`. It stores
data in app-private SQLite, works offline after a cold reopen, and synchronizes
with the household server through the same Rust engine. The desktop AI
companion is **not** ported as a child process.

> **Release status: not released.** Everything below that says "verified" was
> checked on an emulator or in a build. The release gates at the end require
> physical-device checks that have not been done. Do not publish an APK before
> they pass.

## Platform adapters

| Concern                             | Android adapter                                                                                                                                                                                                      |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Credential encryption               | `crates/secure-store`: AES-256-GCM with a non-exportable Android Keystore key; ciphertext in app-private preferences. A plaintext fallback does not exist: if the Keystore is unavailable the person signs in again. |
| App-private storage                 | The core's SQLite lives in the app's data directory (`app_data_dir`).                                                                                                                                                |
| Resume                              | `RunEvent::Resumed` calls `Core::nudge_sync`; there is no daemon.                                                                                                                                                    |
| Browser sign-in (companion-free AI) | Not part of this release; integrated ChatGPT setup is a separate ticket (#28) and must pass its own physical-device proof first.                                                                                     |
| Files                               | The webview file input picks cover photos; shopping PDFs go through `save_file`.                                                                                                                                     |

## Backup and device transfer

`android:allowBackup` is limited by `res/xml/backup_rules.xml` and
`data_extraction_rules.xml`, which exclude the `forkcast_secrets` preferences.
The Keystore key is device-bound and never backed up, so even a copy of the
ciphertext on another device cannot be decrypted; the restored profile keeps
its household link and pending changes but asks the person to sign in again.

## Networking policy

- Servers must use **HTTPS**. Cleartext traffic is disabled in the manifest
  (`usesCleartextTraffic="false"`), and the core also refuses `http://` unless
  the host is `localhost` or a loopback address.
- Self-signed or private-CA servers work only if the CA is installed on the
  device. A LAN deployment should use a name with a real certificate or a
  private CA installed on the device; plain `http://` LAN addresses are not
  supported.
- An unreachable or misconfigured server is shown in Settings (Data
  synchronization) and never blocks local work.

## Supported versions

Android 8.0 (API 26) and newer, arm64 and x86_64. `minSdk` is 24 for the
secure-store module, 26 for the app. Tested: see the table at the end.

## Build

Prerequisites: JDK 17, the Android SDK (platform 35, build-tools 35.0.0, NDK
27.2.12479018), the Rust Android targets, and Node.js.

```sh
rustup target add aarch64-linux-android x86_64-linux-android
export ANDROID_HOME=<sdk>  NDK_HOME=<sdk>/ndk/27.2.12479018  JAVA_HOME=<jdk17>
npm ci
npx tauri android init     # once; generated project is committed
npm run android:build      # a debug APK; add --release for a release build
```

Reproducibility: the toolchain versions above, `Cargo.lock`, and
`package-lock.json` pin everything; the debug APK is signed with the debug key
generated by the Android tooling.

## Signing, upgrades, and distribution

No keys are committed. A release build needs an upload/signing keystore you
create and keep in your secret store:

1. Create a keystore (`keytool -genkeypair ...`) and keep it, with its
   passwords, outside the repository.
2. Provide `keystore.properties` (path, alias, passwords) to the build through
   CI secrets; `gen/android/app/build.gradle.kts` reads it when present.
3. Every release must use the **same signing key** and a higher `versionCode`
   so installs upgrade in place and keep their data. The core migrates its
   database on first launch of the new version; a database from a newer app is
   refused untouched.
4. Distribute through Google Play (use Play App Signing) or as a signed APK.

## Moving data from the old browser version

Same explicit transfer as desktop ([browser-transfer.md](browser-transfer.md)).
Open the transfer page in the old browser, save the file, and choose it under
Settings → Move data from your browser. Nothing depends on the browser and the
app sharing an origin.

### Physical-device release gates (all open)

- [ ] Keystore round trip on a hardware-backed device; restored backup cannot
      read tokens and asks for sign-in.
- [ ] Cooking with the screen locked/backgrounded: foreground timers resume
      correctly on return; no duplicate mutations after process death.
- [ ] Rotation and multi-window keep unsaved forms.
- [ ] Android Back leaves screens predictably and never discards a saved record.
- [ ] Keyboard insets keep focused fields visible on small phones.
- [ ] TalkBack announces statuses and alerts; touch targets meet 48 dp.
- [ ] Image selection from camera and gallery; shopping PDF saved and shared.
- [ ] Populated in-place upgrade from the previous APK keeps all data.
- [ ] HTTPS server access over mobile data and Wi-Fi; unreachable-server error.
- [ ] Integrated ChatGPT loopback authorization (blocked on #28).
